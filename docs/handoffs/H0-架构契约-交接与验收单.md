内容概览（按章）：

1. **技术选型**：SQLite 访问层定稿 rusqlite（bundled），含与 tauri-plugin-sql 八维对比；Rust 15 项 / 前端 11 项依赖；Windows NSIS+MSI 与 Android APK+AAB 构建目标；capabilities 最小权限清单
2. **目录结构**：`src\`（api/stores/pages/utils）与 `src-tauri\`（db/repo/commands/pack）完整目录树
3. **数据库设计**：可执行 DDL——5 表（settings/operators/items/partners/transactions）+ 2 视图（v_inventory、v_transaction_detail）+ 9 索引 + merge_logs 审计表；库存 = ΣIN − ΣOUT − ΣVOID 实时推导；迁移策略与 PRAGMA 约定
   > ⚠️ 本条公式已被契约 v1.1 修订（2026-10-17，A2 环节发现作废 OUT 单回冲方向缺陷）：现为 `ΣIN − ΣOUT + ΣVOID(原单为OUT) − ΣVOID(原单为IN)`，见 [A0 契约 3.3 修订记录](../contracts/A0-架构与接口契约.md)。
4. **IPC 命令契约**：24 条命令分 8 域，每条含 Rust 签名 + TS 类型；统一错误结构 `CommandError{code,message,detail}`；附 `generate_handler!` 注册核对单
5. **数据包格式**：`.cjpack` JSON 单文件 + SHA-256 校验和；导入 7 条前置校验；合并 = UUID 幂等去重 + updated_at LWW（严格大于才覆盖）+ 冲突记录，单事务完成，导入前自动备份
6. **页面与路由**：8 页面对应 8 条 hash 路由，逐页标注依赖命令
7. **横切约定**：UUID v7 主键（时间有序）、设备 ID v4 存 settings、时间戳统一 UTC RFC3339、负库存标红放行判定规则、11 个错误码、日志方案
8. **非目标**：多用户权限 / 云同步 / Excel 旧账导入 / iOS 等 10 项

## 2. 契约遵守情况

本环节即契约源头，无遵守性问题。以下为**经论证的与规划书偏差**（契约中已 ⚠️ 标注，属声明式偏差，请审批时重点确认）：

| # | 偏差 | 理由摘要 |
|---|---|---|
| 1 | transactions 不设 `voided` 列，改为追加 `VOID` 类型单据 + `ref_id` 指向原单 | 保留 voided 列需 UPDATE 原单，与 append-only 硬约束自相矛盾；回冲口径（ΣIN−ΣOUT−ΣVOID）与规划书意图等价 |
| 2 | 共账数据包格式由规划书 `.db/.zip` 细化为 `.cjpack`（JSON 单文件），另保留 `.db` 全量备份作兜底 | JSON 便于版本化与跨端校验；.db 备份满足"随时完整带走"需求 |
