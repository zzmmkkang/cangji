## 1. 技术选型细化

### 1.1 SQLite 访问层：最终结论 = **rusqlite**（Rust 侧）

| 维度 | rusqlite（选定） | tauri-plugin-sql |
|---|---|---|
| SQL 执行位置 | Rust 进程内直调，无 IPC 往返 | SQL 字符串从 WebView 经 IPC 传给插件执行 |
| append-only 强制 | ✅ 在 Rust repo 层集中收口，不暴露 UPDATE/DELETE 流水的 API，前端无法绕过 | ❌ 前端可发任意 SQL，append-only 只能靠自觉 |
| 迁移管理 | Rust 内嵌迁移数组 + `schema_migrations` 表，启动时自动执行（见 3.6） | 迁移在 JS/TS 侧声明，与 Rust 逻辑割裂 |
| 类型安全 | `serde` 结构体 ↔ 表行双向映射，编译期检查 | JS 值手工转换，容易出隐式类型 bug |
| 事务 | 原生 `transaction()`，合并导入等批量操作强一致 | `execute` 逐条走 IPC，弱事务 |
| 并发 | 单连接 `Arc<Mutex<Connection>>` + WAL（理由见下） | 插件内部自管连接池 |
| Android 兼容 | `bundled` feature 把 SQLite 编译进 APK，无系统依赖 | 亦支持，但仍多一层 JS 桥 |
| 数据包合并 | 复用同一 repo 层，合并算法在 Rust 单文件内实现 | 需要把合并逻辑搬进 JS，重复实现 |

**最终结论：选 rusqlite（features: `bundled`）。** 理由：
- **迁移**：`bundled` 内嵌 SQLite 源码，Windows / Android 双端二进制自包含、版本一致，规避系统 sqlite 动态库差异；迁移 SQL 内嵌在 Rust 常量里，A1 搭好骨架后 A2 只改 `db/migrations.rs`。
- **并发**：本应用是单窗口单用户本地记账，所有查询都是短事务。采用 **`Arc<Mutex<Connection>>` 单连接**（`tauri::State` 托管）+ PRAGMA `journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`、`synchronous=NORMAL`。Mutex 排队延迟在记账场景可忽略；WAL 保证未来若需只读连接（如导出统计）可无锁并发读，架构留了升级空间，一期不引入连接池（避免 r2d2 额外复杂度）。

## 3. 数据库设计

DB 文件：`app_local_data_dir()/cangji.db`。命名规范：表名/列名小写下划线；时间戳一律 **RFC3339 UTC 毫秒**（如 `2026-10-17T06:30:00.123Z`，理由见 7.3）。

### 3.1 DDL（v1 全量，可执行）

```sql
-- 迁移记录（框架表，不入数据包）
CREATE TABLE IF NOT EXISTS schema_migrations (
  version    INTEGER PRIMARY KEY,
  applied_at TEXT NOT NULL
);

-- 设置表：键值对；device_id 等本机身份存这里，【不参与数据包合并】
CREATE TABLE IF NOT EXISTS settings (
  key        TEXT PRIMARY KEY,
  value      TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 操作人表：从列表选名字，无密码；name 全局唯一（重名无业务意义）
CREATE TABLE IF NOT EXISTS operators (
  id         TEXT PRIMARY KEY,           -- UUID v7
  name       TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL               -- 统一 LWW 字段，合并按 name 归并
);

-- 货物档案（SKU）
CREATE TABLE IF NOT EXISTS items (
  id          TEXT PRIMARY KEY,          -- UUID v7
  name        TEXT NOT NULL,
  code        TEXT,                      -- 自编码，可空
  spec        TEXT,                      -- 规格
  unit        TEXT NOT NULL,             -- 计量单位：个/箱/kg…
  note        TEXT,
  is_archived INTEGER NOT NULL DEFAULT 0,-- 软删除：1=已归档（见 3.2 说明）
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL              -- 档案可改，合并 LWW 裁决字段
);

-- 往来单位（供应商/客户）
CREATE TABLE IF NOT EXISTS partners (
  id          TEXT PRIMARY KEY,          -- UUID v7
  name        TEXT NOT NULL,
  type        TEXT NOT NULL DEFAULT 'both'
              CHECK (type IN ('supplier','customer','both')),
  contact     TEXT,
  note        TEXT,
  is_archived INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);

-- 进出流水（核心表，append-only：应用层禁止 UPDATE/DELETE，见 4.4/7.6）
CREATE TABLE IF NOT EXISTS transactions (
  id          TEXT PRIMARY KEY,          -- UUID v7（时间有序）
  type        TEXT NOT NULL CHECK (type IN ('IN','OUT','VOID')),
              -- IN=入库 OUT=出库 VOID=作废单（对原单的追加式作废标记）
  item_id     TEXT NOT NULL REFERENCES items(id),
  quantity    REAL NOT NULL
              CHECK (quantity > 0 AND ROUND(quantity, 2) = quantity),
              -- 数量恒为正；VOID 单存原单数量（回冲量）；最多两位小数
  partner_id  TEXT REFERENCES partners(id),   -- 入库=供应商，出库=客户，可空
  operator_id TEXT NOT NULL REFERENCES operators(id),
  device_id   TEXT NOT NULL,             -- 产生本单的设备
  remark      TEXT,
  happened_at TEXT NOT NULL,             -- 业务时间（UTC 存储，前端本地化）
  copied_from TEXT REFERENCES transactions(id), -- 复制来源单（复制上次单据）
  ref_id      TEXT REFERENCES transactions(id), -- VOID 单指向被作废的原单
  created_at  TEXT NOT NULL,             -- 系统记录时间
  updated_at  TEXT NOT NULL              -- LWW 字段（流水合并按 UUID 去重，此字段仅保格式统一）
);

-- 索引：覆盖流水页筛选（按货物/单位/操作人/时间段/方向）与库存 VIEW 聚合
CREATE INDEX IF NOT EXISTS idx_txn_item_time    ON transactions(item_id, happened_at);
CREATE INDEX IF NOT EXISTS idx_txn_time         ON transactions(happened_at DESC);
CREATE INDEX IF NOT EXISTS idx_txn_partner      ON transactions(partner_id);
CREATE INDEX IF NOT EXISTS idx_txn_operator     ON transactions(operator_id);
CREATE INDEX IF NOT EXISTS idx_txn_type         ON transactions(type);
CREATE INDEX IF NOT EXISTS idx_items_name       ON items(name);
CREATE INDEX IF NOT EXISTS idx_items_archived   ON items(is_archived);
CREATE INDEX IF NOT EXISTS idx_partners_name    ON partners(name);
CREATE INDEX IF NOT EXISTS idx_partners_archived ON partners(is_archived);

-- 库存余额：实时推导，不落表。
-- 回冲语义（修订 v1.1）：VOID 按被作废原单方向回冲——作废 IN 减、作废 OUT 加。
-- balance = ΣIN − ΣOUT + ΣVOID(原单为OUT) − ΣVOID(原单为IN)
CREATE VIEW IF NOT EXISTS v_inventory AS
SELECT
  i.id          AS item_id,
  i.name        AS item_name,
  i.spec        AS spec,
  i.unit        AS unit,
  i.is_archived AS is_archived,
  COALESCE(SUM(CASE WHEN t.type = 'IN'   THEN t.quantity END), 0) AS total_in,
  COALESCE(SUM(CASE WHEN t.type = 'OUT'  THEN t.quantity END), 0) AS total_out,
  COALESCE(SUM(CASE WHEN t.type = 'VOID' THEN t.quantity END), 0) AS total_voided,
  COALESCE(SUM(
    CASE
      WHEN t.type = 'IN'  THEN t.quantity
      WHEN t.type = 'OUT' THEN -t.quantity
      WHEN t.type = 'VOID' AND orig.type = 'OUT' THEN  t.quantity
      WHEN t.type = 'VOID' AND orig.type = 'IN'  THEN -t.quantity
    END
  ), 0) AS balance
FROM items i
LEFT JOIN transactions t    ON t.item_id = i.id
LEFT JOIN transactions orig ON orig.id = t.ref_id
GROUP BY i.id;

-- 流水联表视图：流水页/速记主页直接查，避免前端拼名字
CREATE VIEW IF NOT EXISTS v_transaction_detail AS
SELECT
  t.id, t.type, t.quantity, t.remark, t.happened_at, t.device_id,
  t.copied_from, t.ref_id, t.created_at, t.updated_at,
  i.id AS item_id,   i.name AS item_name,   i.unit AS unit,
  p.id AS partner_id, p.name AS partner_name,
  o.id AS operator_id, o.name AS operator_name
FROM transactions t
JOIN items i          ON i.id = t.item_id
LEFT JOIN partners p  ON p.id = t.partner_id
JOIN operators o      ON o.id = t.operator_id;

-- 冲突/合并记录表：每次导入数据包追加一行（审计 + 数据共账页显示"距上次同步"）
CREATE TABLE IF NOT EXISTS merge_logs (
  id                 TEXT PRIMARY KEY,   -- UUID v7
  imported_at        TEXT NOT NULL,
  source_device_id   TEXT NOT NULL,
  source_device_name TEXT,
  source_file        TEXT NOT NULL,
  backup_path        TEXT NOT NULL,      -- 导入前自动备份的 .db 路径
  added_transactions INTEGER NOT NULL,
  updated_items      INTEGER NOT NULL,
  updated_partners   INTEGER NOT NULL,
  new_operators      INTEGER NOT NULL,
  conflicts_json     TEXT NOT NULL DEFAULT '[]'  -- MergeConflict[] JSON
);
```

### 3.2 每张表一句话设计说明

| 表/视图 | 设计说明 |
|---|---|
| `settings` | 本机身份与偏好（device_id、device_name、backup 提醒等），**合并时跳过**，防止把别人的设备身份合进来 |
| `operators` | 选名字不选账号，name 唯一索引兜底；合并按 name 归并、id 以本库为准 |
| `items` | SKU 总量制；`is_archived` 实现规划书"删除"语义（软删，保证历史流水外键不悬空） |
| `partners` | 同上软删；`type` 枚举支撑"两者皆是"的单位 |
| `transactions` | append-only 账本：作废=追加 `VOID` 单（`ref_id` 指原单），永不改写旧行；`copied_from` 支撑复制上次单据的可追溯 |
| `v_inventory` | 库存唯一事实来源，合并后自动正确（规划书：无对账负担）；`balance < 0` 即负库存标红 |
| `v_transaction_detail` | 展示层只读视图，前端不写 join 逻辑 |
| `merge_logs` | 共账审计留痕，同时提供"距上次同步 N 天"的数据源 |
| `schema_migrations` | 框架表，仅 Rust 迁移器使用 |

### 3.3 ⚠️ 与规划书偏差 #1：作废模型

规划书 4.2 同时出现"type 含作废标记""voided 是否作废"与"Σ作废单原数量回冲"。**若保留 `voided` 列，作废就需要 UPDATE 原单，与 append-only 直接矛盾。** 本契约采用：作废 = 追加一条 `type='VOID'`、`quantity=原单数量`、`ref_id=原单 id` 的流水；**删除 `voided` 列**。库存回冲口径与规划书意图等价且严格 append-only。

> **修订 v1.1（2026-10-17，A2 环节发现并修正）**：回冲方向须按被作废原单类型区分——作废 `IN` 单库存减少、作废 `OUT` 单库存**增加**。原公式 `ΣIN−ΣOUT−ΣVOID` 仅对作废 IN 单成立，作废 OUT 15 会错误得出 −15（业务期望回冲 +15）。修正为 `balance = ΣIN − ΣOUT + ΣVOID(原单为OUT) − ΣVOID(原单为IN)`，视图经 `LEFT JOIN transactions orig ON orig.id = t.ref_id` 取原单方向。v1 迁移尚处开发期（v0.1.0 未发布、无存量用户库），按 3.6 "仅禁改已发布迁移"原则直接修订 v1 DDL，同步更新 src-tauri/src/db/migrations.rs。

### 3.4 补充细化（非偏差，A2 直接执行）

- 流水的 `operator` 字段细化为 `operator_id` 外键引用 operators（规划书为文本名字）：人员改名后历史单据自动跟随，统计口径一致。
- `items`/`partners` 的"删除"= 置 `is_archived=1`；列表默认过滤已归档，`includeArchived` 参数可查。
- `items.name`/`partners.name` **不建 UNIQUE**（重名建档允许，应用层提交时提示"已存在同名"但不阻断），`operators.name` UNIQUE。
- 数量精度：DDL 层统一两位小数上限；前端按单位控制输入（整数单位只允许整数），格式化展示在 `utils/format.ts`。

### 3.5 连接与 PRAGMA

打开连接后立即执行：`PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON; PRAGMA busy_timeout=5000; PRAGMA synchronous=NORMAL;`

### 3.6 迁移策略

`db/migrations.rs` 内嵌 `Vec<(u32, &str)>`（version 从 1 开始，v1 = 3.1 全量 DDL）。启动时：读 `schema_migrations` 已应用版本 → 在单个事务内依次执行未应用版本并写入记录 → 失败即 panic 启动中止（不静默带病运行）。后续任何表结构变更必须新增迁移项，**禁止修改已发布的历史迁移 SQL**。

## 5. 数据包格式规范（.cjpack）

### 5.1 ⚠️ 与规划书偏差 #2：格式定稿

规划书 7 章写"数据包 = `.db` 或 zip 快照"。**定稿为 `.cjpack`——单个 UTF-8 JSON 文本文件**（不压缩、不加密）：手机微信/网盘/U 盘直传零障碍、可 diff、可校验、合并时直接反序列化；主库合并场景下裸 `.db` 覆盖会丢本机增量，不适合"合并"语义。同时保留 `backup_database` 导出 `.db` 完整快照作为兜底备份（规划书"一键导出备份"底线）。

### 5.2 文件结构

```jsonc
{
  "magic": "CANGJI_PACK",              // 固定标识
  "schemaVersion": 1,                  // 包格式版本，v1 只接受 1
  "appVersion": "0.1.0",               // 导出时应用版本
  "exportedDeviceId": "…",
  "exportedDeviceName": "…",
  "exportedAt": "2026-10-17T06:30:00.123Z",
  "counts": { "items": 0, "partners": 0, "operators": 0, "transactions": 0 },
  "data": {
    "items": [ /* Item 结构，与 4.2 相同 */ ],
    "partners": [ /* Partner */ ],
    "operators": [ /* Operator */ ],
    "transactions": [ /* Transaction，与 4.4 相同 */ ]
  },
  "checksum": "sha256:<hex小写>"       // 对"除 checksum 外的整个 JSON 规范串"计算
}
```

- 校验和算法：序列化结构体时 `checksum` 置 `None` → `serde_json::to_string` → SHA-256 → hex 小写，前缀 `sha256:`。导入时同法重算比对，不一致 → `E_CHECKSUM` 拒绝。
- 命名：`cangji-pack-YYYYMMDD-HHmmss.cjpack`（设备本地时间）。
- 四表**全量导出**（含已归档档案），与规划书"全量合并包"一致。

### 5.3 导入前校验规则（`pack/model.rs::validate`，任一失败即拒绝，不改库）

1. 文件可读且为合法 UTF-8 JSON（→ `E_PACK_FORMAT`）
2. `magic == "CANGJI_PACK"` 且 `schemaVersion == 1`（→ `E_PACK_VERSION`）
3. 校验和一致（→ `E_CHECKSUM`）
4. `counts` 与 `data` 各数组长度一致
5. 行级校验：必填字段非空、id 为合法 UUID、`type` 枚举合法、`quantity > 0` 且两位小数内、时间戳可解析
6. 引用完整性：transactions 的 `item_id`/`partner_id`/`operator_id` 必须能在**包内或本库**解析到（全量包保证包内自洽）
7. 校验通过后、合并前：**自动执行一次 `backup_database`**（失败 → `E_BACKUP`，拒绝导入，规划书风险 #4）

### 5.4 合并算法（`repo/merge.rs`，单个 `BEGIN IMMEDIATE` 事务内完成）

| 表 | 规则 |
|---|---|
| `operators` | 按 `name` 归并：本库已有同名 → 跳过（id 以本库为准，包内流水 operator_id 需重映射到本库 id）；没有 → 原样插入（保留包内 id） |
| `items` / `partners` | **UUID 幂等 + LWW**：本库无此 id → 插入原样；有 → 比较 `updated_at`，仅当包内**严格大于**本库（相等视为本库新）才覆盖整行（含 `is_archived`），并记入 conflicts |
| `transactions` | **UUID 幂等去重**：id 已存在 → 跳过（append-only 假设同 id 内容一致；若内容不一致，以本库为准并记 conflict，正常不应发生）；不存在 → 插入（operator_id 按 name 重映射） |
| `settings` / `merge_logs` / `schema_migrations` | 不从包内合并；`merge_logs` 追加一条本次导入记录 |
| `v_inventory` | 视图实时推导，合并提交后自动正确，无需对账 |

冲突判定细节（写入 `conflicts_json` 与 `ImportReport.conflicts`）：

```rust

    pub id: String,

    pub incoming_updated_at: String,

}

pub struct ImportReport {

    pub added_transactions: i64, pub updated_items: i64, pub updated_partners: i64,

```

export interface PackCounts { items: number; partners: number; operators: number; transactions: number; }

## 7. 横切约定

### 7.1 UUID 生成

**主键与业务对象一律 UUID v7**（`uuid::Uuid::now_v7()`）。理由：v7 时间有序 → SQLite B-tree 主键插入局部性好（append-only 表顺序写），按 id 排序 ≈ 按时间排序便于调试，仍保留全局唯一性；v4 随机主键在流水表会造成页分裂。`device_id` 用 **v4**（无时间语义诉求，且与业务 id 可区分）。

### 7.2 设备 ID 与设备名

首次启动：settings 无 `device_id` → 生成 v4 写入，此后永不变。`device_name` 默认取系统名（Windows 读 `COMPUTERNAME` 环境变量；Android 用 "Android"），用户在数据共账页可改，存 settings。二者随 `get_app_info` 下发，数据包导出时写入包头。

### 7.3 时间戳与时区策略

- **存储一律 RFC3339 UTC 毫秒 + `Z` 后缀**（`chrono::Utc::now()`）。理由：LWW 依赖字符串比较可靠——带本地时区偏移的 ISO 串（`+08:00` 混 `Z`）字典序≠时间序，会裁决错乱；统一 UTC 后字符串比较即时间比较。
- `happened_at`：用户选的本地业务时间由**前端转 UTC** 后提交；"今天/时间段"筛选由前端把本地日起止转 UTC 传 `dateFrom/dateTo`。`InventoryRow.today_in/today_out` 的"今天"由 Rust 按设备本地时区算边界。
- 展示层由 `dayjs` 本地化渲染；数据包 `exportedAt` 同为 UTC。

### 7.4 负库存标红放行判定（D2 落地）

1. **放行**：`create_transaction` 对 `OUT` 不做任何库存校验，直接落库（Rust 侧无拦截逻辑，也不要加）。
2. **标红**：`InventoryRow.negative = (balance < 0)`；库存总览该行整行红色样式 + 余量红色数字。
3. **即时提示**：记一笔提交成功后前端调 `get_inventory` 取该货物最新 `balance`，为负则 toast 红字"已提交，当前余量 X（低于 0）"。
4. VOID 回冲、合并导入后同样适用（余额由 VIEW 推导，规则自动覆盖）。

### 7.5 错误码表

| code | 含义 | 典型场景 |
|---|---|---|
| `E_DB` | 数据库读写失败 | SQL 错误、约束冲突（非重名类） |
| `E_VALIDATION` | 入参校验失败 | 空名称、quantity 非法、单位为空 |
| `E_NOT_FOUND` | 目标不存在 | 按 id 更新/作废/复制时 |
| `E_DUPLICATE` | 唯一冲突 | `create_operator` 重名 |
| `E_PACK_FORMAT` | 数据包结构非法 | magic 错、counts 不符、行校验失败 |
| `E_PACK_VERSION` | 包版本不支持 | schemaVersion ≠ 1 |
| `E_CHECKSUM` | 校验和不一致 | 传输损坏 |
| `E_BACKUP` | 导入前备份失败 | 磁盘满/路径不可写 |
| `E_IO` | 文件系统错误 | 导出路径不可写、读包失败 |
| `E_PATH_INVALID` | 路径参数非法 | 空路径、扩展名错 |
| `E_INTERNAL` | 未分类内部错误 | 兜底，message 带上下文 |

### 7.6 日志

`tauri-plugin-log`：输出目标 = stdout（开发）+ 文件（`app_log_dir()/cangji.log`，滚动）+ WebView console（前端 `attachConsole`）。级别：release `info`、debug 构建 `debug`。**必须记录**：启动与迁移结果、每条数据包导入/导出（含 counts 与 conflicts 概要）、`E_*` 错误。**禁止**记录任何认为敏感的内容（本应用无密钥，主要是避免大对象 dump）。

### 7.7 其他

- CSP：`tauri.conf.json` 设 `default-src 'self'`，不加载任何远程资源。
- Android 备份引导（规划书风险 #1）：数据共账页当 `last_sync_at`/`last_backup_at` 超过 `settings.backup_remind_days`（默认 7 天）时顶部强提醒条。
- 所有列表查询默认按 `happened_at DESC`（档案按 `updated_at DESC`）。
