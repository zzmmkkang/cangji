## 1. 项目概览

- **系统名称**：仓记 CangJi（GitHub 仓库名：`cangji`）
- **一句话定位**：小商户仓库货物进出记账——本地优先、单文件数据包共账、手机电脑记同一本账
- **首发平台**：Windows 10/11 + Android（同一代码库，Tauri 2 双端构建）
- **技术栈**：Tauri 2 · Vue 3（`<script setup>` + TypeScript）· Pinia · SQLite · Rust
- **核心约束**：无服务器、无账号；流水表只增不改（append-only）；库存余额实时推导；数据包 UUID 幂等合并 + LWW 冲突消解

## 4. 衔接机制

### 4.1 流水线与暂停点

```
A0 → [审批①] → A1 → [审批②] → A2 → [审批③] → A3 → [审批④] → A4 → [审批⑤] → A5 → [审批⑥] → A6 → [终审]
        每个环节结束：编排者产出交接单 → 质量门审查 → 第三方 Agent 审批 → 通过后启动下一环节
```

### 4.2 交接文档（唯一衔接物）

每环节结束，编排者产出 `docs/handoffs/H{n}-<环节名>-交接与验收单.md`，固定五段结构：

1. **成果物清单**——新增/修改的文件、可运行的验证命令
2. **契约遵守情况**——相对 A0 契约的偏差必须逐条显式标注
3. **质量门结论**——code-review 双轴（Standards / Spec）审查结果摘要
4. **遗留问题与风险**
5. **下一环节输入说明**——下一环节 Agent 需要读哪些文件、注意什么

### 4.3 质量门

每环节代码产出后，由编排者运行 `code-review` 技能做双轴审查（Standards：是否符合本仓约定；Spec：是否符合 A0 契约与规划书）。结论写入交接单第 3 节，审查不通过不得交付。

### 4.4 恢复规则

审批通过后，用户对编排者说「继续下一环节」即可；驳回时第三方 Agent 必须在审批单中给出可执行的整改项，编排者整改后重新交付同一环节。

## 5. 第三方 Agent 审批指南

**你是谁**：独立于开发编排者的验收方。你不写代码，只依据交接单声明范围的证据做验收。

**怎么审**：

1. 读当前环节交接单 `docs/handoffs/H{n}-*.md`；
2. 按交接单「验收标准」清单逐项核对，可抽查成果物文件与运行验证命令；
3. 在交接单末尾「审批结论区」填写下述模板；
4. 结论为「通过」→ 用户授权编排者进入下一环节；结论为「驳回」→ 必须给出可执行整改项。

**审批单模板**（直接填写在交接单末尾）：

```markdown
### 审批结论（第三方 Agent 填写）
- 环节：A{n}
- 结论：通过 / 驳回
- 验收标准逐项核对：[x] / [ ]（逐条列出）
- 抽查记录：抽查了哪些文件/命令，结果如何
- 整改要求（驳回时必填，须可执行）：
- 审批人 / 时间：
```

**审批原则**：只审交接单声明范围内的证据，不苛求范围外完美；有疑义先标注为「整改项」而非直接驳回。
